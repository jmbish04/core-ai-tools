Chart ramp — 10 steps, one blue family (hue 250–270)

This is the one deliberate departure from stock shadcn, and it's the hook I'd extend for the revision tree: the repo replaced shadcn's multi-hue chart palette with a single-hue blue ramp. It gives us a legible way to encode depth or generation in the branching tree without introducing a new colour.

Elevation & motion

No drop shadows.Cards separate by surface value + a ring-1 ring-foreground/10. Only the mobile slide-over uses shadow-xl.

Chrome floats.Header and sidebar are bg-background/90 + backdrop-blur, edged at border/40.

Press is physical.Buttons take active:translate-y-px; globally a:active drops to 60% opacity on touch only.

Brisk, never decorative.150–200ms fades and 95% zooms on Radix state. No springs, no bounces. Renders get a calm ambient pulse, nothing more.

What I'd add — and what I'd refuse to add

Four genuine gaps

A node state language.The tree needs queued / rendering / done / drifted / stale-fork on a thumbnail. The repo has processing ambience on a canvas node and nothing else. This is the one new set of tokens I'd propose — built from the existing chart ramp for depth and warning/destructive for drift.

A provenance chip.Web / API / MCP — three-way origin on every node, since a render can arrive from a Claude conversation while you watch. Outline badge with a 10px mono label, no new colour.

A drift verdict treatment.Perspective and dimension drift is the product's headline feature and has no visual precedent in the repo. Needs a real component, not a badge: overlay, delta readout, accept/reject.

Live-arrival motion.The repo's staggered reveal on a 201 is the seed; a socket push needs the same gesture without stealing focus.

Constraints I'll hold

No new hue.Blue ramp, red, amber, emerald. That's the whole allowance. If something needs to stand out, it gets a surface change or the inverted primary — not a colour.

No gradients, no glass, no shadows.Depth comes from four flat surface values and a 10% ring. The only blur in the app is behind fixed chrome.

Copy stays terse and honest.The repo already writes like this — "That render drifted — retry, or tighten the mask." Sentence case, imperative buttons, no emoji, name the recovery.

Every page fits the 256 + 56 frame.Full-bleed tools compute 100dvh − 3.5rem exactly like the workshop does.

One honest caveat: the repo has ~30 pages and I've read the chrome, the tokens, and the workshop in depth — not all 30 page bodies. Before I design the six pages I'll read the closest existing precedents in full (PhotoEditSessionsApp, workshop/*, room-view/*) so the new work forks real code rather than paraphrasing it.
